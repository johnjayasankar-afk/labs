# John Jayasankar · Labs

The site at labs.johnjayasankar.com: the independent products John shipped.
RideLens, Daylight, RailDrop and Gridiron are featured; AgentFit, Cartonry,
KeepFloor and Pricing Hub are also shipped. Every build is told as a story, a schematic
interface that steps through what the product does, and every build's short
link (`/ridelens`, `/agentfit`, ...) hands off to the live product.

Labs is built on the portfolio's own design system (johnjayasankar.com): the
same stylesheet, the same interaction script and the same story engine, so the
two sites read as one. Static HTML and CSS with one small script. No framework,
no runtime dependencies, no CDN and no canvas. Pages are generated from plain
data by a small Python script, and the generated HTML is committed, so hosting
needs no build step.

## Deploy with GitHub and Vercel

1. Put the contents of this folder at the root of a GitHub repository and push.
2. In Vercel choose **Add New → Project** and import that repository.
3. Framework preset **Other**. Leave the build command empty, and leave the
   output directory as the repository root. No environment variables.
4. Deploy. Every push to the default branch redeploys.

To replace the Labs site that is live now, deploy this folder from the Vercel
project that owns labs-rouge.vercel.app: push it to the repository that project
is connected to, or connect this repository to it under **Settings → Git**.

The site's domain is labs.johnjayasankar.com (`./set-domain.sh` changes it). In
that project open **Settings → Domains**, add `labs.johnjayasankar.com`, and
Vercel serves it with HTTPS; because johnjayasankar.com already uses Vercel's
nameservers, no DNS record has to be added by hand. The labs-rouge.vercel.app
address keeps working, and can be set to redirect to the new domain there too.

`vercel.json` is generated by the build. It supplies clean URLs, the eight
short links below, caching and security headers, including the
Content-Security-Policy. `.vercelignore` keeps the generator, the story lab and
these docs off the CDN.

| Short link | Opens |
|---|---|
| `/ridelens` | https://ride-lens2.vercel.app/ |
| `/daylight` | https://daylight-app-wine.vercel.app/ |
| `/raildrop` | https://rail-drop3.vercel.app/ |
| `/gridiron` | https://gridiron-pink-chi.vercel.app/ |
| `/agentfit` | https://agent-fit2.vercel.app/ |
| `/cartonry` | https://cartonry.vercel.app/ |
| `/keepfloor` | https://keep-floor.vercel.app/ |
| `/pricing` | https://pricing-hub-seven.vercel.app/ |

They are temporary (307) redirects, the same as before, so a product can move
without breaking a link anyone saved. Change a destination in `tools/data.py`
(`route` and `live`), not in `vercel.json`, then rebuild.

To point the site at another domain before deploying:

```bash
./set-domain.sh labs.example.com
```

That rewrites the one place the domain lives (`tools/data.py`) and regenerates
canonical URLs, Open Graph and Twitter tags, the sitemap and robots.

## Run it locally

```bash
python3 tools/serve.py . 4402
```

Then open http://localhost:4402. The server behaves like Vercel: clean URLs, the
short-link redirects and headers from `vercel.json` (re-read on every request)
and a real 404 page. A plain `python3 -m http.server` will not follow the short
links, so use this one.

## Edit content

| File | Holds |
|---|---|
| `tools/data.py` | the site's name, domain and links; the home page and 404 copy; and the eight builds: name, line, blurb, what it does, stats, the rule it keeps, short link and live URL, bay titles and phases |
| `tools/stories.py` | the story engine, shared with the portfolio, and the RideLens, Daylight, RailDrop and Gridiron stories |
| `tools/labs_stories.py` | the AgentFit, Cartonry, KeepFloor and Pricing Hub stories |

Then regenerate:

```bash
python3 tools/build.py
```

The build writes `index.html`, `404.html`, `vercel.json`, `sitemap.xml`,
`robots.txt` and `assets/js/labs-data.js` (the command palette index), and stamps
CSS, JS and image URLs with content hashes so a deploy never serves a stale
file. It refuses to finish if a page contains an em or en dash, a link, in-page
anchor or ARIA reference that resolves nowhere, or a duplicate id, and it checks
that every bay has one story step per phase.

To add a build, add an entry to `BUILDS` in `tools/data.py` and register a story
under the same slug. `featured=True` gives it a full row on the home page;
otherwise it gets a card in the Also shipped band.

## Structure

```
index.html  404.html
vercel.json                   generated: clean URLs, short-link redirects, headers
assets/css/site.css           the portfolio's design system, with a Labs section near the end
assets/js/site.js             the portfolio's script: header and Builds menu, reveal and
                              count-up, showcase tabs, bays and stories, palette, keys
assets/js/labs-data.js        generated palette index
assets/fonts/                 Inter (variable), IBM Plex Mono 400/500
assets/img/                   favicon, og.jpg, the portfolio card in the Builds menu
tools/                        generator, data, stories, dev server, CDP driver      (not deployed)
_stories.html _stories.js     story lab                                             (not deployed)
_og.html                      source for the link-preview card                     (not deployed)
```

`assets/css/site.css`, `assets/js/site.js` and `tools/stories.py` are the
portfolio's files. Labs adds to them rather than changing them: the Labs
section of the stylesheet (its tag, the Builds menu, the eight rules, the 404
index and the four Labs-only stories), and palette entries for builds in the
script. If the portfolio's design moves on, copy those three files across, keep
the Labs section of the stylesheet, and rebuild.

## Stories and bays

The home showcase uses the full bay (a phase list with captions, a
plain-language reading of the interface and a rail whose playhead shows where
the story is); the featured rows use the compact bay (phase pills under the
story); the Also shipped cards play their stories while in view.

- Every page is written with each story at its resting phase, so it is complete
  before any script runs, and for anyone who prefers reduced motion. A bay holds
  that phase for one step (3.4 seconds), then walks its phases while it is on
  screen. Choosing a phase holds it; choosing it again resumes. Digits pick the
  phase of the bay in view.
- Container queries decide what each size shows: floating notes above 640px, a
  denser window below 430px.
- Stories are schematic. Every figure in them is published by the product
  itself: RailDrop's sample board, Daylight's Balanced preset, Gridiron's replay
  of captured real games, AgentFit's reference output for Support triage,
  Cartonry's 200 × 150 × 100 mm example, KeepFloor's Linen tote listing and
  Pricing Hub's Profit check example.
  RideLens ranks quote types rather than providers, because nothing published
  says which provider wins.

In the story files, an element that belongs to some phases carries `data-on`
(`"1"`, `"1-2"`, `"2-"`); `site.js` adds `is-on` while the bay is in one of them,
and the CSS decides what that looks like. `press()` is a button a named pointer
presses, `typed()` is text that types itself in, and `count()` is a figure that
runs to its value. The resting value is always the real figure.

The lab renders every story at the sizes the site uses:

```bash
python3 tools/stories_lab.py
python3 tools/serve.py . 4402
```

- `http://localhost:4402/_stories?only=agentfit&step=1` shows one story at one
  phase in every frame size; `?auto=1` plays them all.
- `http://localhost:4402/_og` is the 1200x630 link-preview card, saved as
  `assets/img/og.jpg`.

`tools/shoot.mjs` drives headless Chrome over the DevTools protocol (Node 22 or
later, no dependencies) for screenshots and in-page audits.

## Keyboard

`⌘K` / `Ctrl K` or `/` opens the palette, which finds any build, its case study
or a section; `?` lists the keys. `j` / `k` move through the builds and sections,
`Enter` opens what is highlighted, digits pick the phase of the bay in view, `y`
copies a link, `e` copies the email, `t` or `g g` goes to the top, and `Esc`
clears the highlight.

## Design notes

- **Palette.** The portfolio's: a porcelain ground (`#f8f6f1`) with a faint dot
  grid, near-black ink, deep forest (`#13241b`) for weight, mint for what
  settled. Inside the stories, amber marks a hold or a cost, sky marks context
  and work in progress, and mint marks outcomes.
- **Type.** Inter for display and reading, IBM Plex Mono for labels, counts and
  the row keys inside stories. Both are self-hosted open-licence fonts.
- **Motion.** The header floats into a pill after the first scroll. Blocks rise
  into place the first time they arrive and figures count up once. The showcase
  advances on a timer that pauses on hover, focus, when off screen or in a
  hidden tab. Stories cross-fade between phases, and a story state that is not
  showing stops animating. Everything honours `prefers-reduced-motion`.
- **Contrast.** `--ink-2` is 7.3:1 and `--ink-3` 5.2:1 on the ground. Tone halves
  of headings are only used at large sizes.
